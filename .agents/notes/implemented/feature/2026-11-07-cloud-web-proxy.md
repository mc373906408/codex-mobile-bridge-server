# Agent Note: 云账号 Web 入口与桌面网站透传

Status: implemented

## Problem

现有网站仅允许管理员使用，普通账号不能从浏览器访问自己的电脑。用户要求 18787 提供云登录后免桌面批准的 Web 访问，且网站内容始终来自桌面当前版本。

## Decision

在同一 Go 进程和数据库增加独立 Web Origin、Cookie、会话用途及出站桌面代理通道。每个请求核对账号、目标电脑、服务资格与会话；撤销、退出和到期终止相关流。手机入口和管理入口继续使用原 Origin。

服务器只提供登录与电脑列表；/d/{gateway_id}/ 下的网页资源、预览和业务请求均通过桌面出站 WSS 获取，不打包聊天网页。Web 采用服务器可见明文的 TLS 代理，不冒用手机安装或批准记录。传输有界、支持取消和流式响应，断线不重放写入。

入口页使用独立的 `web_client.css`，沿用桌面网站的字体、配色、图标和控件风格，并跟随系统深浅色。登录表单与电脑目录通过 `hidden` 互斥显示，电脑卡片保留在线、离线、旧网关和资格不足时的原有连接限制；管理后台继续使用自己的样式。

桌面现有独立的网页许可总开关，默认关闭；开启后仍免逐浏览器批准。云端不保存本机许可，桌面在线而 Web 通道未就绪时提示检查桌面网页访问设置或版本，不把离线直接断言为用户关闭。

## 记录归属

[服务端审查](../../implemented/architecture/2026-11-03-server-architecture-and-scope-audit.md)部分重叠：普通 Web 是新增的账号信任边界，手机端到端密文约束继续有效。[持久中继](../../implemented/architecture/2026-11-05-persistent-relay-v2.md)部分重叠：保留手机协议和资格规则。本次检索没有应删除或归档的重复提案。

## Alternatives considered

- 浏览器端加密可使正常中继不处理明文，但用户选择更少网页适配的 HTTPS 代理。
- 静态资源导出可让资源独立于电脑在线，但要同步桌面更新，用户明确取消此方案。

## Testing

使用本机隔离 PostgreSQL 运行 `go test ./...` 全部通过（含原管理、账号和手机中继用例），`go vet ./...` 通过，Linux amd64 服务端编译通过。新增 API 覆盖 Cookie/Origin/CSRF/会话用途、跨账号、资格、禁用与退出；真实 HTTP/WebSocket 测试覆盖桌面实时版本、20 MiB 上传下载、大文件并发限制、SSE 刷出、取消、到期、截断报错、超大元数据和未知写入不重放。

首次数据库回归发现旧迁移测试写死迁移总数，改为断言失败迁移没有记录；满帧上传夹具缺少 WebSocket ReadLimit，按协议长度修正夹具后通过。桌面四组 Chromium/WebKit 宽窄视口通过实际生产资源与预览等流程；数据为合成账号，未访问真实会话。部署步骤见 [Web 文档](../../../../docs/web-client.md)，线协议见 [Web-v1](../../../../protocol/web-proxy-v1.md)。

Caddy 2.10.2 的 `validate` 通过标准双站点配置；Compose 2.39.2 合并两种 overlay 后，核对 18787→18787、原 443/8787→443、各自 Origin 与 Caddyfile 挂载均正确。工具下载后校验官方发布校验和；未在本机启动公网监听或签发生产证书。两仓笔记树、格式、归档校验通过，测试专用 Go/Python/PostgreSQL 已停止。

生产于 2026-11-07 使用现有证书部署 18787，部署前保留数据库、旧镜像、Compose 与 Caddy 配置，并在备份恢复出的临时数据库完成迁移演练。2026-11-08 复核 server/database 健康，HTTPS 与 P2P 容器运行；3 个账号、2 台网关、7 个手机安装和 7 条绑定保留，004 迁移存在。首次部署归档的 54 个源码文件与当时本机源码摘要一致。

本机 Windows 网关更新后，Edge 使用用户现有账号登录，成功显示在线电脑、透传桌面聊天列表并读取当前真实聊天；未触发桌面浏览器批准。18787 公网 TLS 验证及页面返回 200，未登录目录和桌面 API 返回 401，跨 8787 Origin 的 Web 请求返回 403；原 8787 能力接口返回 200 并继续公布手机 v2 和 P2P 能力。生产发送、审批、文件写入和手机真机连接不在本次实际操作覆盖范围内。

2026-11-08 首页样式更新通过 JavaScript 语法检查、API/config/webproxy 包测试与 Linux amd64 构建；本轮未启动隔离数据库，数据库测试不计作重跑。浏览器使用合成账号检查登录错误、登录/退出、离线电脑和空列表，并检查深浅色及 390px 布局。新部署 `cloud-web-home-20261108T020751` 的 56 个生产文件仅有 5 个首页相关文件与首次部署不同。首次上线因服务器 DNS 临时失败自动回退；调整为本机 HTTPS 探测后重新发布成功，仍验证公用域名证书和 SNI。线上 HTML/CSS/JS/图标摘要一致，8787 返回 200，database/HTTPS/P2P 容器不变。Edge 的真实账号目录、原版聊天列表、390px 无横向溢出和桌面布局通过，首页控制台无错误。

## Consequences

云服务处理 Web 明文，继续禁止记录正文与凭据。数据库新增用途列和最多 12 小时 Web 会话，原 native/admin 不能使用 Web 凭据。退出/撤销清理流但保留手机连接；资源缓存为 private，HTML no-store。单文件 20 MiB、每浏览器 8 流、每桌面 64 流；大传输每浏览器 1 个、每桌面 2 个。未来扩大文件上限、跨进程路由或新增 WebSocket 业务时应重审这些约束。

提供标准 443 与现有 8787 的两种部署 overlay；18787 使用独立容器监听，已有证书及续期须保留。回退只需禁用 Web Origin/站点并恢复镜像，新增数据库列可保留。当前生产入口和本机桌面已通过真实读取验收，其他旧版桌面仍需更新；手机真机与生产写操作需单独验证。
