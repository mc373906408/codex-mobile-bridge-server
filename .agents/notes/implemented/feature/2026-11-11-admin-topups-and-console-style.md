# Agent Note: 管理员直接充值与统一云控制台样式

Status: implemented

## Problem

管理员目前只能生成兑换码或撤销有效期，人工处理购买、补偿时无法直接增加指定账号的服务天数。8787 的首页和管理台仍使用米色衬线风格，与 18787 的蓝色控件、无衬线字体和深浅色界面不一致。

## Decision

hosted 用户列表提供“充值天数”对话框，显示目标账号与现有有效期，默认 30 天，允许 1–3650 整数天及可选备注。提交后以服务器 UTC 当前时间和现有有效期的较大值顺延；只允许已验证、未停用的普通用户，充值不修改账号或设备授权。selfhost 不显示并拒绝该接口。

管理写入继续采用 Origin/CSRF 与事务内管理员身份复查。`POST /v1/admin/users/{id}/topups` 接受天数、备注与请求 UUID。充值、请求回执和前后有效期审计同事务提交；`006_admin_topups.sql` 以管理员／请求 ID 唯一保存回执，相同请求与参数返回原结果，不同参数返回冲突。账号锁使充值与兑换、撤销串行执行；不自动重试不确定的写入，前端在管理员隔离的 sessionStorage 保存同一次请求，重载后仍可人工核实。

首页、管理员登录、首次改密、密码重置和管理台统一采用 18787 的字体、蓝色重点、灰白表面、圆角控件及跟随系统的深色模式。保留现有导航、分页、活动、兑换码导出和审计功能，手机宽度以纵向卡片和可滚动导航呈现。18787 仍保持独立的普通账号会话与路由。

## 记录归属

[官方购买二维码下发](2026-11-11-sponsorship-qr-endpoint.md)仅向桌面展示购买渠道，与本篇管理员直接充值分离，不授予账号资格或改变充值审计。

已检索活跃笔记中的充值、管理台、后台、样式与 18787。与[管理和审计](../../implemented/bug-fix/2026-11-04-admin-management-and-audit.md)部分重叠，复用权限和事务审计；[云 Web 入口](../../implemented/feature/2026-11-07-cloud-web-proxy.md)持有独立入口与样式参考，不改变其会话边界。注册活动与批次兑换继续独立，无需替换；无重复的直接充值提案。

## Alternatives considered

仅继续生成兑换码可以复用现有发码流程，但用户明确需要管理员直接充值，因此增加独立的账号充值操作。复用普通用户兑换接口会混淆管理员代充值和客户持有码兑换的权限与审计，故分别记录。

## Testing

PostgreSQL 18.1 使用本轮独立数据目录和 127.0.0.1:55439 监听，`BRIDGE_TEST_DATABASE_URL` 已明确指向测试实例；最终 `go test -json ./...` 的 139 个测试事件通过，零失败、零跳过，`go vet ./...` 通过。充值回归验证有效／过期／首次充值、同请求回执复用、跨账号 ID 冲突、6 路并发顺延、审计失败全部回滚，以及普通用户、失效管理员、跨 Origin、缺少 CSRF、自建模式、未验证／停用／管理员目标被拒。账号删除按原兑换回执的规则级联删除充值回执，不阻塞删除，历史审计继续保留；回归覆盖这一边界。

19 项 Node UI 回归通过，包含已有用户搜索／分页／设备、兑换码与活动用例，以及充值默认值、收据确认、存储失败不发送、重复点击禁用、未知结果跨重载使用同一请求。实际生产 Go 页面在合成账号下通过 Edge Chromium/WebKit × 1280/390 px × 深浅色 × hosted/selfhost 的 16 组检查，包含首页、密码重置、登录、管理台、实际加天数／审计和兑换码生成，零页面异常与横向溢出；截图已检查。证据位于忽略目录 `.tmp/admin-upgrade-20261111/`。

## Consequences

管理员可以直接处理人工服务天数，减少生成并转交兑换码的步骤；代价是新增持久充值回执，需要随数据库备份保留。会话存储不可用时界面拒绝提交，确保网络结果未知后仍有可核实的请求 ID。服务端授权仍是唯一依据，界面隐藏不授予权限。

新回执表采用增量迁移，保留现有账号和有效期。该功能记录人工服务天数变更，不采集支付信息、不收款。本轮未部署到生产、未给真实账号充值；18787 的实际页面仅作为视觉参考。
