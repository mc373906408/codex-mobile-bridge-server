# Agent Note: 邮箱注册体验活动按期管理与原子赠送

Status: implemented

## Problem

邮箱证明注册原先创建空服务资格，必须兑换才能使用托管服务。用户要求注册赠送默认 7 天，并由服务端后台控制多期活动；已确认只有活动期间新注册账号参加、每个账号一次、同时只有一期未结束活动，客户端不增加宣传或领取入口。

## Decision

仅 hosted 管理活动与赠送。草稿可编辑名称、1～3650 天、开始时间、可选截止时间和名额；启用后规则固定，停止永久结束，历史和已发放服务保留。草稿与排期均占用唯一当前位置，上一期停止、到期或名额用尽后才能创建下一期。迁移只预建默认 7 天草稿，重启不重置；发布与正式启用分别执行，部署不自动启用活动。

`005_registration_campaigns.sql` 追加活动与赠送记录，数据库唯一约束保护单个未结束活动和账号一次赠送，赠送历史的 UPDATE/DELETE 由触发器拒绝。注册事务在创建账号后，使用与管理操作相同的事务级活动锁及活动行锁，按锁后数据库 UTC 时间判定资格，写入服务到期、赠送、计数和审计；失败全部回滚。验证码不预占名额，客户端重试不重放赠送。截止点不包含，按连续 24 小时计算服务天数，兑换继续顺延。

管理接口复用管理员认证、CSRF、事务内角色/会话复核及游标分页。只在注册成功路径发放，不给旧账号补发，不增加设备、网页或通知授权。后台以浏览器时区展示输入并标明时区。读取时计算自然到期状态，写操作在相同锁下结算结束，无定时任务依赖。

已检索 proposed、implemented、rejected 中的注册、邮箱、服务资格、赠送和活动。[全局省察](../../implemented/architecture/2026-11-03-server-architecture-and-scope-audit.md)的“注册不增加服务天数”在有效活动下由本篇取代，其邮箱证明与授权边界继续成立；[当前注册结构](../../implemented/simplification/2026-11-04-prerelease-account-and-binding-schema.md)、[管理员审计](../../implemented/bug-fix/2026-11-04-admin-management-and-audit.md)、[批次兑换](../../implemented/feature/2026-11-04-redemption-batch-account-limit.md)部分重叠，分别继续持有唯一注册流程、管理员权限和兑换限制。其他部署、推送和中继记录无关，未发现重复活动方案，不移动或归档。

## Alternatives considered

- 单个永久赠送开关实现最少，但没有每期规则与历史归属；用户选择保留多期历史、单期运行。
- 并行活动可组合推广，但用户明确下一期必须等上一期结束，因此数据库和界面一起限制，而不是配置优先级或叠加规则。
- 登录时补发或异步任务能减少注册事务工作，但会把老用户纳入或导致注册成功却未发放；因此赠送与注册同事务。
- 只用活动行锁可减少序列化，但活动结束并更换当前行时会出现读到旧行而漏掉新一期的窗口。管理与发放共用短事务 advisory lock，低频注册的临界区串行，保持切换边界明确。

## Consequences

管理员可控制每期规则、额度和历史，注册与赠送不可部分成功，服务资格复用原有到期与兑换机制，客户端接口无需变化。限制的是唯一邮箱账号，不是自然人，不合并邮箱别名或新增设备识别。活动锁串行化注册最后的短临界区；若注册吞吐或锁等待成为瓶颈，需要重新衡量并发策略，并保留切换期不漏发的保证。数据库错误必须失败而非悄悄跳过赠送。后台规则启用后冻结，纠正需结束并创建下一期；已发放服务时间不因活动结束缩短。历史保留增加数据库空间，暂不提供清理入口。线上部署已完成，正式活动未启用。旧程序拒绝未知迁移，不能直接指向带 005 的数据库降级；一旦产生活动修改或赠送记录，必须保留历史，禁止直接删表或覆盖旧备份回滚。
