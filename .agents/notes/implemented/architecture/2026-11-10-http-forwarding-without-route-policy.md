# Agent Note: 云网页代理取消接口和方法清单

Status: implemented

## Problem

桌面和 App 的接口清单曾阻止已授权业务到达 HTTP 处理器；服务端 Web 代理还只转发 GET/POST，使客户端删除清单后仍有不同链路能力不一致。用户明确要求所有链路取消逐接口白名单、黑名单，允许云服务正式上线前调整协议。

## Decision

Web 代理取消 GET/POST 筛选，将合法 HTTP 方法和非 GET/HEAD 正文完整转发。HEAD 允许描述性 Content-Length，但流内正文仍为零。桌面 HTTP 处理器决定路由是否存在、方法是否支持、业务权限和文件边界。

云端继续校验登录会话、Origin/CSRF、账号资格、电脑归属和撤销状态；报文长度、受限请求头、流控及断线取消保持原有职责。Noise 业务是密文中继，服务端不解密或新增接口策略；P2P 引导节点的固定目的地和禁止业务中继配置属于网络职责，不在删除范围内。未知结果不自动重放。

## 记录审计

- [云网页透传](../feature/2026-11-07-cloud-web-proxy.md)：部分重叠，HTTP 方法传输规则由本篇持有；账号信任、资源适配和此前部署事实继续有效。
- [P2P 资格](2026-11-06-easytier-p2p.md)：网络引导的中继配置与业务接口清单无关，保留原决定。
- 已检索活跃笔记，无需删除、归档或拒绝的重复提案。

## Alternatives considered

- 保留 GET/POST 限制可少处理几种请求，但会继续造成合法接口在云通道不可用，违背用户的全链路移除要求。
- 改用少量接口黑名单仍会增加第二套业务权限规则，因此不采用。

## Testing

隔离 PostgreSQL 下 `go test ./internal/api ./internal/webproxy -count=1` 通过；两个包的 `go vet` 和 Linux amd64 服务端编译通过。真实 HTTP/WebSocket 验证新增路径的 POST/PUT/PATCH/DELETE/OPTIONS 正文、HEAD 长度、CSRF 拒绝和 PATCH 未知写入只发送一次；原有流控、文件限制及会话撤销回归通过。数据库为本机独立测试集群，不使用生产数据，结束后已停止。

## 部署验证

用户随后明确授权远端部署。2026-11-10 生产服务更新为 `bridge-server:http-forwarding-20261110-d35a7a5`，运行二进制 SHA-256 为 `b1964fe45ef8c6b6081fd899b5a67e200211ded9cd3132d988aa294d4e13e871`，与本机构建产物一致。以线上 `d35a7a5` 源码为基线，145 个归档文件中只有本轮 4 个 Go 实现/测试文件变化；本机后续提交仅含部署文档，其他工作树改动不混入这次镜像。源码清单 SHA-256 为 `723239286867b1f278d2715cdcd59abfa1452cba49a46ef7376fd165dff5c7af`。

沿用固定 SSH 主机密钥、现有 Compose 和运行镜像的基础层。切换前生成加密 PostgreSQL 备份并通过 `pg_restore --list` 校验；旧镜像和配置保留用于仅回退服务进程，不回滚数据库。无 schema 变更，账号、权益、网关、手机、绑定、兑换和活动等 10 张表的 81 条记录摘要一致；手机 `last_seen_at` 属于正常连接状态，不参与摘要。database、HTTPS、P2P 的容器 ID、镜像和启动时间不变。

远端健康检查、6 个页面资源摘要、公网 8787/18787 TLS 校验通过。7 种方法的未认证请求均返回 401，跨 Origin 返回 403；公网额外核对 PATCH/HEAD 到达认证处理，不再返回代理方法清单的 405。本机桌面重新连接云端，Lenovo 保留登录态并重新读取 Codex 会话列表。部署脚本、源码归档、备份记录和结果保留在忽略目录 `.tmp/http-forwarding-deploy-20261110/` 及远端对应 release 目录，不提交凭据或备份。

## Consequences

新增桌面 API 不再需要服务端同步方法清单。HTTP 处理器承担当次业务授权，不能依赖代理隐含拒绝。本轮远端变更已经部署并通过健康、认证和手机读取核验；实际生产写操作、所有客户端/传输组合及 iOS 签名真机仍须分别验收。
