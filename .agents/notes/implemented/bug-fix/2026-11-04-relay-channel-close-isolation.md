# Agent Note: 中继请求通道关闭不应中断桌面连接

Status: implemented

[持久中继 v2](../architecture/2026-11-05-persistent-relay-v2.md)进一步改为按绑定复用会话、按流结束请求并隔离背压。本篇保留原自然关闭竞态及身份隔离理由。

## Problem

用户反馈云服务连接不稳定。当前部署未重启、无 OOM、资源充足，手机连续六次受信 HTTPS 健康检查均成功（约 80–106 ms），但这些不覆盖中继通道。隔离测试确认 `Hub.remove` 删除已结束手机通道并发送 Close 后，桌面 worker 的 finally 回发 Close 被 `forward` 判为 unauthorized route；`Serve` 因此关闭共享桌面连接，并取消其余手机通道。每个 HTTP 请求使用独立手机通道，正常请求结束就可能触发这条竞态。

## Decision

网关连接在内存中最多记住 128 个已关闭通道与绑定身份，寿命为一分钟。只丢弃该网关已经拥有、已关闭通道的迟到 Close/Record，仍拒绝未知通道、错配 binding 和跨网关路由；已经取消但未移除的手机也按已关闭处理。手机通道绑定实际网关连接对象，网关重连后旧通道不能被转发或把关闭记录带到新连接。记录随网关连接结束释放，不持久化业务内容。响应记录仍按原队列顺序先交付再关闭，不增加写入自动重放，不放宽身份/资格/绑定校验。

单个手机发送队列过载只取消该手机通道，避免一个慢消费者关闭共享网关；网关总发送队列过载仍关闭其连接，维持有界背压。真实 WebSocket 关闭交错、其他手机持续通信及非法路由拒绝由回归测试验证。部署镜像为 `bridge-server:relay-stability-1fd6a04962d31b61`，原地使用当前数据库，保留新注册账号和当前绑定，不再次清库。

## 记录归属

检索当前笔记后，[架构省察](../architecture/2026-11-03-server-architecture-and-scope-audit.md)部分重叠，持有有界队列及中继授权边界；[管理与审计](2026-11-04-admin-management-and-audit.md)测试主动撤销目标手机，不覆盖自然请求关闭；[当前结构部署](../process/2026-11-04-current-schema-server-deployment.md)是此前一次性新库部署，不用于本次重复初始化。没有既有自然关闭竞态提案。

## Alternatives considered

- 全部未知通道都忽略最简单，但会掩盖伪造路由，故只容忍当前网关已经拥有且刚关闭的明确通道。
- 手机不关闭连接或桌面不回 Close 能降低触发频率，但取消/网络中断仍会留下在途记录，服务端必须正确隔离通道生命周期。
- 每次请求重试能掩盖读错误，但写入结果未知时不能自动重放，且无法解决共享链路反复断开，因此修正中继路由状态。

## Testing

`TestPhoneCloseAcknowledgementDoesNotDisconnectGateway` 在旧代码上明确失败，返回 `unauthorized route`；修复后同场景、迟到 Record、慢/已取消手机不影响共享网关，未知通道、错配 binding、跨网关和重连代次仍拒绝。关闭记录容量/过期有独立测试。真实 WebSocket 回归保持一个网关和一个持续手机通道，另一个通道交替由手机/桌面发起关闭，每轮再注入迟到记录和关闭回执并核对持续通道双向数据。

本地 PostgreSQL 18.1 完整 Go suite 共 109 个测试事件通过、无跳过，vet、模块校验通过。此前重复 socket 回归通过 400 轮，最终 Linux 构建在部署主机独立数据库再通过 400 轮；发布可执行文件自身启动与 admin 初始化 smoke 通过，合成库/容器随后清理。Windows CGO 禁用，未执行 race，不能把上述结果视为竞态检测器通过。

## Consequences

正常请求结束不再拆掉共享桌面中继，其他在途请求也不被单个慢手机连带取消。代价是每网关有界、短期关闭记录，过期或超出容量后的未知通道仍按错误处理。更新服务端容器使现有中继重连一次，手机和桌面无需重新安装或配对。已复现并修正这条确定缺陷，但当时日志未记录每次关闭原因，不能断言用户此前所有断线都仅由它造成；实际网络抖动和授权失效仍可能断开。健康检查不能替代真实用户会话端到端验收，所有写操作仍保持未知结果不重放。
