# Agent Note: 未上线账号和绑定使用当前数据库结构

Status: implemented

## Problem

[架构省察](../architecture/2026-11-03-server-architecture-and-scope-audit.md) 的 F2 复现旧邮箱验证接口启用预存密码的问题。App 和桌面已采用自动目录，服务端却仍有手动配对、旧验证码表和历史升级迁移。用户明确项目尚未上线，旧数据库与绑定数据无需保留；这些分支没有继续维持的前提。

## Decision

PostgreSQL 只由 `001_current.sql` 建立当前结构。已有迁移历史必须属于当前代码，旧开发库明确报错，不自动改写或清空。配对表、`pairing_id`、旧请求/批准/拒绝路由和对应 Store 方法全部移除；登记建立同账号目录关系，桌面 access 开关继续用 revision 防止迟到开启覆盖关闭。

邮箱注册只保留 `registration-code → registration-verify → register`。短期证明与密码一起创建新账号；任何已有账号均不能被注册流程覆盖。旧 `verification/verify-code`、账号绑定验证码、预建未验证账号及旧密码激活路径被删除。邮件只属于注册挑战或密码重置，重置密码与 selfhost 管理员创建用户各自保留。持久化猜测限额、重发失效、单次消费、账号隔离和通知资格检查继续执行。

## 记录归属

F2 与本篇部分重叠：原省察保留修复前的复现事实，当前状态互链到本篇。F1 由[推送撤回修复](../bug-fix/2026-11-04-push-withdrawal-independent-of-desktop-access.md)持有，本次统一数据库初始化不改变其缩减权限契约。桌面和 App 分别记录 IPC、证明存储及 SQLite 的清理；本仓没有其他同主题 proposed 或 rejected 笔记。

## Alternatives considered

- 继续迁移旧账号与绑定能减少已有安装升级时的中断，但用户明确不保留这些开发数据；它还留下激活旧密码的第二条路径，因此移除。
- 保留旧接口但返回兼容回执，能让旧客户端继续运行，却让同一产品保留两套注册与授权语义，因此旧路由直接不可用。
- 自动清空不支持的数据库可以省去手工初始化，但错误配置也可能指向有价值的数据库；选择明确拒绝，由操作者指定新库。

## Consequences

注册和设备授权各只有一条受支持的入口，初始化无需复现历史表结构，旧密码激活缺口关闭。代价是旧开发库和旧客户端不能直接升级；三端需协同使用当前版本并重新建立开发身份。当前版本内正常关闭、重启、重新登录和撤销仍有各自持久化语义，并非每次启动都清空数据。管理员初始认领和全局管理范围仍由原架构省察记录。

## Testing

隔离 PostgreSQL 18.1 上的完整 Go 回归有 98 个通过事件，无跳过；`go vet` 通过。测试包括新库二次初始化、旧迁移历史拒绝、旧路由不可用、注册证明并发单次消费、已有账号不覆盖、目录与关闭栅栏、跨手机/账号推送撤回及 queued/leased 取消。日志在本机 `D:/github/.codex-tools/architecture-closeout-20261104/`；没有操作部署数据库、真实账号、SMTP 或厂商推送。
